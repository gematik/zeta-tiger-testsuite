[#UC_01_19]
== UseCase_01_19: Client ressource anfrage fachdienst SC 405

.UseCase_01_19
[cols="1,1a",options="autowidth"]
|===
| *Titel:* | Client ressource anfrage fachdienst SC 405

| Akteur: |
*MA einer LEI*

| weitere Akteure: |
- *ZETA Client*
- *PEP HTTP Proxy*
- *Resource Server*

| Auslöser: |
Ein MA einer LEI fordert eine Ressource über den ZETA Client an, verwendet aber eine für den Endpunkt nicht erlaubte HTTP Methode.

| Kurzbeschreibung: |
Der ZETA Client sendet eine Anfrage mit gültigem Access Token und DPoP Nachweis an den PEP HTTP Proxy.
Der PEP HTTP Proxy leitet die Anfrage mit unveränderter Request-Zeile an den Resource Server weiter.
Der Endpunkt unterstützt die verwendete HTTP Methode nicht, daher wird der Zugriff mit
``405 Method Not Allowed`` abgewiesen.

| Vorbedingung: |
Der ZETA Client ist registriert, authentisiert und autorisiert.

| Nebenbedingung: |
Der geschützte Endpunkt ist so konfiguriert, dass nur eine bestimmte HTTP Methode (z. B. ``GET``) erlaubt ist.

| Ablauf: |
1. MA startet den Abruf einer geschützten Ressource über den ZETA Client mit einer nicht erlaubten HTTP Methode.
2. Der ZETA Client erstellt einen *DPoP Nachweis*.
3. Der ZETA Client ruft die Ressource am PEP HTTP Proxy auf:
- ``POST /resource`` (Beispiel für nicht erlaubte Methode)
- ``Authorization: DPoP ... (Access Token)``
- ``DPoP: ... (DPoP Token)``
4. Der PEP HTTP Proxy validiert die Nachweise.
5. Der PEP HTTP Proxy leitet die Anfrage mit unveränderter Request-Zeile an den Resource Server weiter.
6. Der Resource Server antwortet mit ``405 Method Not Allowed``.
7. Der PEP HTTP Proxy gibt die Antwort ``405 Method Not Allowed`` an den ZETA Client zurück.
8. Der ZETA Client informiert den MA, dass die Anfrage mit der gewählten HTTP Methode nicht unterstützt wird.

| Nachbedingung: |
Der Ressourcenzugriff wurde abgewiesen.
